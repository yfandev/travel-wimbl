## Finding: Super is rate-limited on this account

In both runs, a single sequential Super call (T1) failed with `429 Too many requests. Reason: max_requests_limit (orchestrator)` on all four attempts (1 s / 2 s / 4 s backoff), and parallel Super calls needed retries (run 2: only 3/5 succeeded). Super does work when calls get through (T2 tool calls passed in both runs, T3 structured output passed in run 1). Nano and Lightning were not limited this way. Before Super carries the controller, verifier and learning roles at volume: ask Crusoe about the account's Super request limit, and give Super its own lower concurrency cap and longer backoff.

Price estimates exist only for Super (third-party, ComputePrices); other models log `cost_estimate_usd: null`.
